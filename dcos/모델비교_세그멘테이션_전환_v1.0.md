# 모델 비교 분석: 분류 모델에서 시간축 세그멘테이션 모델로 전환 (v1.0)

작성일: 2026-07-15

로컬 백엔드(backend/)의 낙상 판정 모델을 기존 Window3BestModelInference의
분류 모델(best_model.pt)에서 신규 InhouseSegmentationRealtime의 시간축
세그멘테이션 모델(temporal_segmentation_fixed_delay.pt)로 교체하며 두
파이프라인을 비교 분석한 문서다.

## 1. 요약

- 전처리(피처 추출)는 두 모델이 완전히 동일하다. 파라미터, 수식, 정규화
  상수까지 같아서 backend/features/ 코드는 수정 없이 그대로 쓴다.
- 모델은 "3초 윈도우 전체가 낙상인가"를 답하는 이진 분류에서, "3초 윈도우
  내부 64개 시간 구간 각각이 낙상인가"를 답하는 시간축 세그멘테이션으로
  바뀌었다.
- 판정 정책은 임계값 0.468 + 최근 5윈도우 인과 다수결에서, 윈도우 중앙
  확률 >= 0.5 단독 판정(후처리 없음)으로 바뀌었다. 판정이 가리키는 시각이
  "1.5초 전"으로 명확해졌다 (고정 지연 1.5초).
- 교체 후 backend 엔진 출력을 신규 패키지 기준 추론(infer.py)과 비교해
  161개 윈도우 전부에서 확률 오차 3.6e-7 이내, 판정 라벨 100% 일치를
  확인했다.

## 2. 패키지 구성 비교

| 항목 | 기존 | 신규 |
|---|---|---|
| 전처리 패키지 | ACF_Scalogram_FeatureExtraction | InhouseSegmentationRealtime (features.py에 통합) |
| 모델 패키지 | Window3BestModelInference | InhouseSegmentationRealtime |
| 가중치 | weights/best_model.pt (93.8MB, 254 텐서) | weights/temporal_segmentation_fixed_delay.pt (93.5MB, 299 텐서) |
| 기준 추론 스크립트 | infer_validation.py | infer.py (원본 CSV, 피처 npz, 폴더 일괄 지원) |
| 동봉 데이터 | 검증 세트 피처 | 학습 데이터 77개 녹화, 15,320 윈도우 피처와 세그멘테이션 레이블 |

기존에는 전처리와 모델이 별도 패키지였지만 신규 패키지는 원본 CSV 파싱,
피처 생성, 추론, 판정 규칙까지 한 패키지에 담겨 있어 기준 구현 대조가
쉬워졌다.

## 3. 전처리 비교: 동일

신규 패키지 data/config.json과 backend FeatureConfig를 항목별로 대조한
결과 모든 파라미터가 일치한다.

| 파라미터 | 값 (양쪽 동일) |
|---|---|
| window_seconds / stride_seconds | 3.0 / 0.25 |
| raw_csi_pairs / drop_pair_indices | 245 / [121, 122] |
| target_subcarriers / omega | 30 / 30 |
| moving_variance_radius_seconds | 0.4 |
| freq_min_hz / freq_max_hz | 1.0 / 170.0 |
| image_size (S3) | 224 |
| th_scmax / kappa / carrier_hz | 1.0 / 1.0 / 2.4e9 |
| acf_lag_seconds / lag_output_bins / time_bins | 0.4 / 128 / 64 |
| acf_clip_percentile | 99.5 |

계산 경로도 동일하다: 균일 그리드 리샘플 -> Q-metric 기반 스트림 선택
-> PCA motion signal -> CWT(gmw) S3 scalogram (224,224) + PCA-ACF
(1,128,64). 신규 features.py의 함수들(select_streams, select_pc_signal,
general/vertical/horizontal_denoise, compute_acf)은 backend
features/common.py, features/acf.py와 수식이 같다.

입력 정규화 상수도 두 체크포인트가 완전히 같다 (feature_a mean 0.08702,
std 0.16221, feature_b mean 0.05160, std 0.21383). 즉 신규 모델도 같은
피처 분포로 학습되었고, backend 피처 코드를 그대로 쓸 수 있다.

차이는 실행 형태뿐이다. 신규 패키지는 녹화 전체를 한 번 리샘플한 뒤
윈도우를 자르는 오프라인 구조이고, backend는 링버퍼에서 3초 윈도우를
꺼내 윈도우 단위로 리샘플한다 (fs 0.25Hz 양자화와 CWT scale 캐시는
backend 쪽 실시간 최적화이며 수식에는 영향이 없다).

## 4. 모델 구조 비교

| 항목 | 기존 DualBranchResNet | 신규 DualBranchTemporalSegmentationModel |
|---|---|---|
| 입력 | S3 (224,224), PCA-ACF (1,128,64) | 동일 |
| 백본 | ResNet18 인코더 2개 (S3, ACF 각각) | 동일 |
| 인코더 활용 | 최종 avgpool 임베딩(512차원)만 사용 | layer1~4 특징 피라미드를 모두 사용 |
| 헤드 | 임베딩 concat -> MLP -> 2-class 로짓 | 시간축 사영(피라미드별 1D conv, 32ch) -> branch 결합 -> dilated temporal residual decoder (dilation 1,2,4,8, 128ch) -> 64-bin 로짓 |
| 출력 | 윈도우 1개당 낙상 확률 1개 (softmax) | 윈도우 내부 64개 시간 구간별 낙상 확률 (sigmoid), 구간당 약 47ms |
| 체크포인트 구성 | model_config(backbone, embedding_dim, fusion_hidden_dim, dropout, image_size) | model_config(output_bins, pyramid_channels, decoder_channels, decoder_dilations, dropout, image_size)와 최상위 backbone, embedding_dim, source_dropout, fixed_delay 배포 규칙 |

핵심 차이는 시간 해상도다. 기존 모델은 3초 윈도우 어딘가에 낙상이 있는지만
알 수 있어 판정이 가리키는 시각이 모호했다. 신규 모델은 윈도우 내부
어느 시점이 낙상인지 구간별로 출력하므로, 윈도우 중앙의 확률을 뽑아
"정확히 1.5초 전 시점" 판정으로 쓸 수 있다.

## 5. 판정 정책과 지연 비교

| 항목 | 기존 | 신규 |
|---|---|---|
| 임계값 | 0.468 (검증 세트 튜닝 값) | 0.5 (체크포인트 fixed_delay.default_threshold) |
| 후처리 | 최근 5윈도우 인과 다수결 | 없음 (겹침 평균, 최소 지속시간, 간격 연결, 다수결 필터 모두 미적용) |
| 판정 의미 | 최근 3초 윈도우 전체의 낙상 여부 | 1.5초 전 중앙 시점의 낙상 여부 |
| 확정 지연 | 모호함. 다수결 충족까지 최소 3틱(0.75초) 추가, 검증에 쓴 mode5(중심 기준)와 의미 불일치 문제 존재 | 고정 1.5초. 검증과 실시간의 판정 의미가 같음 |
| 상태 전이 | IDLE, SUSPECT(raw 양성, 다수결 미확정), FALL, COOLDOWN | IDLE, FALL, COOLDOWN (SUSPECT는 다수결 중간 상태였으므로 제거) |

기존 구조의 가장 큰 문제는 검증 시 사용한 후처리(mode5, 중심 윈도우 기준,
미래 2윈도우 필요)를 실시간에서 그대로 쓸 수 없어 인과 다수결로 근사했고,
그 결과 실시간 성능이 검증 지표와 달라질 수 있었다는 점이다. 신규 모델은
"윈도우가 끝날 때 중앙 시점 결과를 공개한다"는 규칙 자체가 실시간 설계라
검증과 실시간의 의미가 일치한다.

## 6. 성능 지표

기존 모델(best_model.pt, 체크포인트 val_metrics, 검증 13개 녹화 375 윈도우):

| 지표 | 값 |
|---|---|
| accuracy | 0.949 |
| balanced accuracy | 0.798 |
| fall precision / recall / F1 | 0.600 / 0.625 / 0.612 |
| AUROC | 0.945 |

신규 모델은 체크포인트에 검증 지표가 실려 있지 않다. 동봉된 77개 녹화
(15,320 윈도우)는 전량 학습에 사용되었으므로 패키지 데이터로 잰 수치는
일반화 성능이 아니며, README도 신규 테스트 데이터로 별도 평가하라고
명시한다. 패키지 자체 검증 값은 다음과 같다.

- strict 체크포인트 로드 통과
- 재생성 피처와 기준 피처 최대 오차 2.4e-4 (float16 저장 오차 수준)
- 원본 CSV 2윈도우 smoke test 기준 대비 최대 오차 2.5e-8

따라서 정량 비교(기존 대비 정확도 개선 폭)는 현재 불가능하고, 팀 차원의
신규 테스트 데이터 수집 후 평가가 필요하다. 이번 전환의 근거는 판정
의미의 명확화(고정 지연 1.5초), 검증-실시간 의미 일치, 후처리 제거로
인한 동작 단순화다.

## 7. 교체 적용 내역

| 파일 | 변경 |
|---|---|
| backend/inference/model.py | DualBranchResNet 제거, DualBranchTemporalSegmentationModel 이식 (신규 패키지 model.py와 1:1) |
| backend/inference/engine.py | 신규 체크포인트 로드, 64-bin 추론(predict_bins)과 중앙 확률 선형 보간(predict). 기본 체크포인트 경로를 InhouseSegmentationRealtime/weights/로 변경 |
| backend/detector.py | 인과 다수결 제거, 중앙 확률 단독 판정. 기본 임계값을 체크포인트 값(0.5)에서 읽음. SUSPECT 상태 미사용 |
| backend/main.py | --threshold 기본값을 체크포인트 위임(None)으로 변경 |
| backend/README.md | 파이프라인, 기본 경로, 판정 규칙 설명 갱신 |
| src/lib/backend.ts, src/routes/index.tsx | proba_fall 의미(1.5초 전 시점) 주석과 라벨 갱신 |
| .gitignore | InhouseSegmentationRealtime/ 추가 |

WebSocket 페이로드 키(detect_state, proba_fall, threshold, fall_count,
last_fall_time)는 그대로라 관제 화면 로직 변경은 없다. FALL 확정 시
ntfy 알림 훅(on_fall)도 동일하게 동작한다.

## 8. 교체 검증 결과

1. 기준 추론 일치: 신규 패키지 infer.py를 CPU로 실행한 결과와 backend
   FallInferenceEngine 출력을 20260705_005402_RX1_S1_R1_T1_D1 녹화
   161개 윈도우에서 비교. 확률 최대 오차 3.6e-7, 판정 라벨 100% 일치,
   낙상 윈도우 12개 동일.
2. 상태머신: 확률 시퀀스 [0.1, 0.3, 0.9, 0.95, 0.2, 0.1] 입력 시
   IDLE, IDLE, FALL, FALL, COOLDOWN, COOLDOWN 전이와 fall_count 1회,
   임계값 재정의(--threshold) 동작 확인.
3. 지연: bench_pipeline.py (fs 166.67Hz, MPS) 기준 피처 중앙값 14.1ms,
   추론 중앙값 14.4ms, 합계 약 28ms로 0.25초 스트라이드 이내. 벤치마크의
   p90 이상치는 합성 입력의 fs 지터로 CWT scale 캐시가 빗나가는 기존
   동작이며, 실제 수신기는 fs가 166.67Hz로 고정이라 캐시가 적중한다.
